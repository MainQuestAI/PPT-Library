## 3. 版本演进

### 3.1 Wave A — 生产基础（v1.5 + v1.6）

**目标：** 从功能 Beta 进入可靠、可度量的本地生产版本。

#### v1.5 — Production Core & Contract Closure

| Task | 交付物 |
|---|---|
| 1.5-A | 基线验证报告 + 5 ADR（identity/job staging/writer model/publishing/schema numbering） |
| 1.5-B | Contract Registry（7 JSON Schema）+ `capabilities`/`contract` CLI + 稳定错误码体系 |
| 1.5-D | 内容指纹（slide/deck revision id）+ 身份 registry + Schema v5 迁移引擎 |
| 1.5-E | Job Engine（状态机/stage/checkpoint/idempotency/cancel/resume） |
| 1.5-F | 增量治理（affected scope 检测 + 手动 override 保留 + 一致性校验） |
| 1.5-G | PPTX 安全（archive 限制/路径穿越/外部关系清单/嵌入对象告警） |
| 1.5-H | 版本升级 1.5.0 + CHANGELOG + release notes |

**关键决策：** 身份采用分层模型（revision id 内容推导 + canonical id 持久化），Job Engine 自研轻量（无 Celery 依赖），Single Writer 避免 SQLite 全局锁竞态。

#### v1.6 — Search Quality & Benchmark

**目标：** 从"能搜到"升级为"检索质量、性能、降级行为均可证明"。

| Task | 交付物 |
|---|---|
| 1.6-A | FTS5 全文检索（BM25 排序 + Search Document 模型） |
| 1.6-B | Vector Backend 接口 + SqliteScanBackend（可插拔 ANN） |
| 1.6-C | RRF 融合 + Search Profile（default / deck_master） |
| 1.6-D | Reranker 接口 + Egress Policy（默认禁止云端） |
| 1.6-E | Query Trace（全链路 provenance：backend 计数/时延/模型版本/fallback） |
| 1.6-F | Evaluation v2（Recall/Precision/MRR/nDCG + graded relevance + 发布门禁） |
| 1.6-G | Scale Harness（10k/50k/100k 合成数据 + 硬件 manifest） |
| 1.6-H | Search Release Gate（8 项检查固化默认 Profile 和发布证据） |

**关键修复：** BM25 权重对齐到 14 列 FTS 表（原 12 权重错位导致 title 权重落到 UNINDEXED 列）；snippet 读取列索引从 1 修正为 5（body_text）；FTS query sanitizer 剥离双引号防 OperationalError。

## 6. 关键架构决策（ADR 摘要）

5 个 ADR 固化于 `docs/adr/`：

| ADR | 决策 | 理由 |
|---|---|---|
| 001 | 分层身份（内容指纹 revision + 持久化 canonical） | 平衡内容确定性与人工治理；纯内容哈希无法支持跨 revision 的逻辑资产 |
| 002 | 自研轻量 Job Engine | local-first 不引入 Celery/Redis；v1.9 Server Mode 可扩展 Queue/Worker |
| 003 | Single Writer + Staging Batch | 避免 SQLite 全局锁竞态；extract/render 并行，commit 串行 |
| 004 | PyPI + GitHub Release 双渠道 | 可用性 + 可发现性 + 严格 release gate |
| 005 | 线性 Schema 版本号 + journal + backup | 简单直观；迁移可追溯可恢复 |
